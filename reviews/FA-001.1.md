## Non-blocking observations

### `with_sha256()` permits re-hashing under the same identity

The implementation allows:

```python
first = discovered.with_sha256(hash_a)  # same id, sha256=hash_a
second = first.with_sha256(hash_b)  # same id, sha256=hash_b, hash_a != hash_b
```

This does **not** block FA-001.1 because:

- The audit trail lives in `DomainEvent` instances, not in `DiscoveredFile` snapshots. Each `FILE_HASHED` event is an independent, immutable record with its own `id` and `timestamp`. A second hash produces a second event — the first is not overwritten or destroyed.
- Legitimate scenarios include: file modified between hashes, error correction, or explicit re-classification. Restricting to single-hash would be a policy decision belonging to the scanner layer, not a domain correctness constraint.
- If single-hash policy is desired later, it belongs in FA-002+ (scanner logic), not in the domain model's `with_sha256()` method.

## Verification of M1–M4

### M1 — Deep immutability: VERIFIED

**`DomainEvent.payload`**:
- Field type is `Mapping[str, Any]` — `MappingProxyType` at runtime after construction.
- `_freeze_payload` validator calls `deep_freeze()` after JSON-serializability check.
- `deep_freeze()` recursively converts dicts → `MappingProxyType`, lists/tuples → `tuple`.
- Tests confirm: top-level item assignment raises `TypeError`; nested list mutation raises `AttributeError`; nested dict mutation raises `TypeError`.
- `_serialize_payload` field_serializer calls `deep_thaw()` for `model_dump()`/`model_dump_json()`, converting back to plain dict/list.
- Round-trip tests (`test_serialization_round_trip_json`, `test_serialization_round_trip_dict`) pass, confirming no shared mutable state is reintroduced.

**`FileProposal.reasons`**:
- Field type is `tuple[str, ...]` — immutable at runtime.
- Tests confirm: `.append()` raises `AttributeError`; item assignment raises `TypeError`.
- `Field(default_factory=tuple)` avoids shared default (verified by `test_default_payload_is_not_shared_between_instances` pattern, though not explicitly tested for reasons — the `tuple` type itself guarantees immutability).

**Serialization correctness**:
- `deep_thaw()` converts `MappingProxyType` → `dict`, `tuple` → `list`. This is standard JSON-compatible output.
- `deep_freeze()` and `deep_thaw()` are inverses. No semantic inconsistency detected.

No regressions found.

### M2 — ScanRun.evolve(): VERIFIED

- `_EVOLVABLE_FIELDS = frozenset({"status", "completed_at", "files_discovered"})` — immutable class-level constant.
- `evolve()` computes `disallowed = set(changes) - self._EVOLVABLE_FIELDS` and raises `ValueError` with field names in the message.
- Tests confirm rejection of: `id` change, `root_path` change, `started_at` change, unknown/typo fields (`statuss`).
- Lifecycle fields update atomically: `test_evolve_allows_lifecycle_fields_only` confirms `status` and `files_discovered` update together while `id`, `root_path`, `started_at` are preserved.
- Model invariants revalidated: `evolve()` calls `type(self).model_validate(...)` which runs all validators including `_validate_completion_state` (the `model_validator(mode="after")`). Tests confirm `COMPLETED` without `completed_at` is still rejected after evolve.

The `**changes: Any` API does not introduce material correctness issues. Invalid values for evolvable fields (e.g., `status="invalid"`) are caught by Pydantic field validation during `model_validate`.

No regressions found.

### M3 — SHA-256 lifecycle: VERIFIED

- `with_sha256(sha256: str) -> "DiscoveredFile"` returns `type(self).model_validate({**self.model_dump(), "sha256": sha256})`.
- Returns a new instance: `hashed is not original` confirmed.
- Preserves `id`: `hashed.id == original.id` confirmed.
- Preserves all unrelated state: path, size_bytes, created_at, modified_at all match.
- Invalid SHA-256 rejected: `with_sha256("not-a-valid-hash")` raises `ValidationError`.
- Original unchanged: `original.sha256 is None` remains true after `with_sha256()` call.

The identity paradox from FA-001 is resolved: `FILE_HASHED` events can now reference a `DiscoveredFile` with its hash set, without creating a new identity.

No regressions found.

### M4 — Derived path metadata: VERIFIED

- `filename` is a `@property` returning `self.path.name` — single source of truth, no independent field.
- `extension` is a `@property` returning `self.path.suffix.lstrip(".").lower()` — derives from path, normalized.
- Constructor rejects injected values: `extra="forbid"` prevents passing `filename` or `extension` as constructor args. Tests confirm `ValidationError` on attempt.
- Extensionless files: `LICENSE` yields `extension == ""` (empty string). Correct.
- Multi-suffix files: `archive.tar.gz` yields `extension == "gz"` (pathlib's `.suffix` behavior — final suffix only). Documented in docstring. Consistent with contract.
- Windows paths: `C:\Users\test\notes.TXT` yields `filename == "notes.TXT"`, `extension == "txt"`. Correct.

No regressions found.
