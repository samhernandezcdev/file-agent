## Minor

### m1. `.env.local` classified as UNKNOWN, not OTHER

A file like `.env.local` has pathlib extension `local`, which is not in `_EXTENSION_TABLE`. The dotfile rule is gated on `if discovered.extension: return None`, so it never fires. Result: `.env.local` is UNKNOWN (confidence 0.0), while `.env` is OTHER (confidence 1.0).

This is a first-match-wins edge case, not a bug — the rule precedence is documented and consistent. But it may surprise a caller who expects all dot-prefixed names to be OTHER. If this matters, a future rule could match `.<name>.<variant>` patterns, but it's outside FA-005's scope.

**Affected code**: `rules.py:159` (dotfile rule gate), `DiscoveredFile.extension` (`file.py:47-53`)

**Why it matters**: Low — UNKNOWN is a safe, valid result. A future rule-table update or additional rule can address `.env.*` variants without architectural changes.

### m2. `_miss_reason` hardcodes `_rule_` prefix stripping

`classifier.py:67`:

```python
name = rule.__name__.removeprefix("_rule_")
```

If a rule function is renamed without the `_rule_` prefix, the reason string silently shows the full function name instead of a clean label. This is a minor coupling between naming convention and output format — not a correctness issue.

**Why it matters**: Cosmetic. The reason string is for debugging/explainability, not programmatic consumption.

### m3. Determinism test doesn't verify `classified_at` timestamp

`test_determinism.py` uses the default `_utc_now` clock. It checks `category`, `confidence`, `reasons`, and `classifier_id` for equality, but `classified_at` is never compared because the default clock returns different timestamps on each call.

The `fixed_clock` fixture exists in `conftest.py` but is unused by the determinism tests. A test injecting `fixed_clock` into `FileClassifier` and comparing the full result (including `classified_at`) would close this gap.

**Why it matters**: The `classified_at` field is part of the durable `FILE_CLASSIFIED` event. Determinism of the full result is worth proving, not just inferring from the rule logic.

### m4. Persistence integration test recreates store per test

`test_persistence_integration.py:21-28` creates a fresh `FileAgentStore` for every test. The `test_repeated_classification_appends_history_not_overwrite` test correctly proves append-only behavior within a single test, but there's no test proving that two independent stores (simulating process restart) see the same historical events.

**Why it matters**: Low — FA-004 already proved SQLite persistence survives process restart. The classifier-specific claim (append-only) is tested. But a cross-store visibility test would strengthen the guarantee.

### m5. `.com` classified as EXECUTABLE — historically correct, could surprise

`.com` is in `_EXTENSION_TABLE` as `FileCategory.EXECUTABLE`. The `.com` extension historically refers to DOS MZ executables, which is correct per the EXECUTABLE definition ("directly launched/loaded by the OS by name"). However, on modern Windows `.com` could also refer to COM component registrations, which are more analogous to `.dll` (also EXECUTABLE). The classification is consistent and correct under the current taxonomy, but the dual meaning of `.com` is worth noting for future rule-table evolution.

**Why it matters**: No action needed — the EXECUTABLE definition covers both cases. Flagged for awareness only.

## Architectural observations

1. **Zero filesystem I/O — verified.** The AST guardrail in `test_no_filesystem_access.py` checks every `.py` file in `src/file_agent/classifier/` for forbidden imports (`os`, `shutil`, `io`), forbidden calls (`open()`), and forbidden `Path` methods (`stat`, `exists`, `read_text`, etc.). The guardrail is strictly stronger than FA-002/FA-003's (which permit reads). The classifier code itself imports only `dataclasses`, `datetime`, `collections.abc`, and `file_agent.domain` — no I/O-capable modules.

2. **Taxonomy is policy-free.** `FileCategory` values (`DOCUMENT`, `IMAGE`, ..., `EXECUTABLE`, `OTHER`, `UNKNOWN`) describe what a file appears to be, not what should happen to it. The `EXECUTABLE` docstring explicitly states it "exists to preserve a distinct signal for a future policy layer" — the classifier does not implement any such policy. No destination, risk, or action semantics leak into `ClassificationResult` or the rule set.

3. **Rule precedence is clean and documented.** Fixed order: extension → special filename → dotfile → UNKNOWN. First-match-wins. The extension rule is checked first because most real files have extensions; the special filename rule handles extensionless well-known names (`Dockerfile`, `README`); the dotfile rule handles dot-prefixed config names (`.gitignore`, `.env`). UNKNOWN is the explicit fallback, not an error.

4. **OTHER vs UNKNOWN is correct.** OTHER = positive recognition that doesn't fit a primary bucket (currently only dotfile convention). UNKNOWN = no rule matched. The dotfile rule correctly returns OTHER with confidence 1.0; no rule incorrectly turns "not recognized" into OTHER.

5. **Confidence semantics are honest.** Deterministic match → 1.0. UNKNOWN → 0.0. No intermediate values exist in the current rule set (there's no probabilistic or heuristic rule). The `__post_init__` validation rejects out-of-range values with `ValueError` — no silent clamping. The score is documented as "not probability and authorizes no action."

6. **ClassificationResult invariants are enforced at construction.** Frozen dataclass, non-empty reasons, non-empty classifier_id, aware datetime required and normalized to UTC, confidence in [0.0, 1.0]. A malformed `ClassificationResult` is impossible to construct — the invariants are tested in `test_result_invariants.py`.

7. **Provenance is durable.** `CLASSIFIER_ID = "rules-v1"` is a stable string, not a version number. Every `FILE_CLASSIFIED` event includes it in the payload. When the rule tables change in a future release, the ID should be bumped to a new string (e.g., `rules-v2`), ensuring old events remain interpretable by their provenance.

8. **Explainability is factual.** Matched results cite the specific extension or filename that triggered the rule. UNKNOWN results include one miss reason per rule, each showing the extension and filename that were checked. Reasons never claim content knowledge — only extension/filename evidence.

9. **Persistence integration is a thin composition boundary.** `classification_event()` creates a `DomainEvent` from a `ClassificationResult`. The classifier package has zero dependency on `file_agent.persistence` — no SQLAlchemy, no sessions, no SQLite. The caller passes the event to `FileAgentStore.record_event()`. Repeated classification of the same observation appends historical events (different `DomainEvent.id`), never overwrites.

10. **Event payload is complete and JSON-compatible.** `FILE_CLASSIFIED` includes: `category` (string), `confidence` (float), `reasons` (list of strings), `path` (string), `classifier_id` (string). All values are JSON-serializable. The `DomainEvent` model deep-freezes the payload into `MappingProxyType`, ensuring immutability after construction.

11. **Determinism is structural.** Same `DiscoveredFile` state → same classification output. No randomness, no external state, no filesystem state, no environment variables, no locale-sensitive operations. The clock is injectable for testing. The rule functions are pure — they depend only on `DiscoveredFile` fields.

12. **Rule tables are correct for the initial set.** Extensions are normalized (lowercased) before lookup. The special filename rule lowercases the filename for case-insensitive matching. No duplicate entries. No unreachable rules. The EXECUTABLE/CODE distinction is consistent with the docstring definition (OS-launched by name vs. requires explicit interpreter).

## Summary

FA-005 is a clean, minimal implementation that correctly answers "what kind of file does this appear to be?" without overstepping into organization policy. The architecture boundary is well-maintained, the invariants are sound, and the test coverage is thorough. The minor issues — `.env.local` edge case, unused `fixed_clock` in determinism tests, and a few missing test scenarios — don't affect correctness or safety.
